What actually happens between that keystroke and report.md landing on disk

Three parties talk to each other during one run: this machine, the device being scanned, and DeepSeek's API. The diagram below traces every hop between them in the order it actually executes.

Stage by stage

  1. 01
    your machine

    uv run run_crew 192.168.1.1 activates the project's .venv and resolves run_crew — the console-script entry in pyproject.toml pointing at network_vuln_scanner.main:run.

  2. 02
    your machine

    Importing main.py runs a proxy check before anything else: a 1-second connection attempt to whatever host:port HTTPS_PROXY points at. Unreachable — VPN client off — clears the proxy vars for this process only, so later API calls go direct instead of hanging.

  3. 03
    your machine

    main.run() reads the IP from sys.argv and builds NetworkVulnScanner().crew() — two agents (network_scanner, report_analyst), two tasks, Process.sequential — then calls .kickoff().

  4. 04
    your machine → target

    The scanner agent's first tool call: a full 65535-port nmap sweep with service/version detection and vulners CVE matching, capped at 30 minutes.

  5. 05
    your machine → target

    SNMP enumeration runs next regardless of the TCP result, since SNMP is UDP and scanned separately. Capped at 150 seconds total so a filtered port fails fast instead of the 10-minute hangs it used to take.

  6. 06
    your machine → target

    ssh-audit --skip-rate-test runs only if port 22 came back open. The flag exists because ssh-audit's DH-rate test crashes on native Windows with AttributeError: module 'socket' has no attribute 'AF_UNIX'.

  7. 07
    your machine → DeepSeek

    With all three tool outputs collected, the scanner agent's own reasoning step calls deepseek-chat to compile everything into one structured findings block — the first hop that leaves your network.

  8. 08
    your machine → DeepSeek

    The reporting agent receives that block as context and calls deepseek-reasoner to rank every finding Critical → Info with a fix, and to note the manual hydra credential check that's deliberately not automated.

  9. 09
    your machine

    Because the reporting task declares output_file='report.md', CrewAI writes the agent's final answer straight to report.md in the project root.

Two things that used to break this

FIXED

A dead VPN proxy hung every LLM call for hours. HTTP_PROXY/HTTPS_PROXY pointed at a local Clash instance that wasn't always running. Stage 02's loopback probe now checks it on every run and bypasses it automatically when it's down — no manual toggling needed.

FIXED

LLM calls had no timeout. deepseek-chat now caps at 180s and deepseek-reasoner at 300s, both with 2 retries — so a stalled request fails within minutes instead of hanging indefinitely.
